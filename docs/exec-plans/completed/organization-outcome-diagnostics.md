# ExecPlan：零合并结果诊断

创建：2026-09-07。更新：2026-09-08。执行者：Codex。状态：诊断、维度修复及真实测试完成；语义质量未达标。

## 目标与证据

用户报告整理完成但总览仍为 325 条。经现有 MCP 连接分页读取，当前 325 条记忆全部只有一个来源；总览的 State `counts()` 查询 `memory_public_items`，统计的是当前可见记忆，不是原始来源贡献数量。没有发现字节完全相同的条目，部分条目存在包含与中英文重叠。

当前代码将无候选、正常非等价、模型明确不确定、无效输出降级均记为 `independent`。无效输出还被缓存成不确定，旧缓存无法恢复其原始有效性。因此“325 条完成、87 次调用”不能证明 87 次有效语义判断，也不能确定生产零合并的原因。

## 约束、范围与设计

遵守 [ADR-0031](../../adr/0031-incremental-memory-organization.md)、[记忆规范](../../memory-system.md)、[接口](../../interfaces.md)、[数据模型](../../data-model.md) 与 [架构](../../architecture.md)。保持完整等价才合并、来源资格、Vault 隔离和规范发布边界。不放宽等价判定，不修改生产数据。最初只做只读诊断；9 月 8 日依用户授权扩大到隔离副本中的真实模型测试及已复现维度缺陷修复。

1. Memory 在后续处理时分别记录无候选、包含、非等价、不确定、无效输出、输入超限、分组上限等结果；缓存附加由应用写入的校验分类，不信任模型声明。旧缓存有效性明确归为未记录。
2. State 提供按 Vault 汇总的条目结果、缓存校验分类和关系数量。只在用户请求详情时统计缓存 JSON，不加入每两秒任务进度查询；仅返回固定分类及数字，不包含内容、路径或模型输出原文。
3. Admin 增加只读整理诊断接口，管理页按需加载结果；任务卡直接显示已有合并计数。结果说明区分当前条目与累计缓存关系数，旧结果不追溯猜测。
4. 回归验证缓存跨版本读取、模型不能伪造校验分类、聚合隔离、接口认证与 UI 零合并展示。文档明确本地诊断修复与生产零合并根因仍待运行数据区分。

## 风险与恢复

结果诊断使用现有文本字段和缓存 JSON。真实测试发现的维度缺陷另由前向迁移 0026 修复重排，已部署的迁移 0024／0025 保持不变。旧结果保持可读，旧无效输出与模型主动不确定无法可靠区分，不能把旧数据冒充已验证结果。诊断不自动清缓存或重新检查，不改变已有检查点和记忆数量。

## 结果

本计划的诊断与本地验证已完成，详见[实测报告](../reports/organization-real-model-validation-20260908.md)。真实混合测试完成 325/325 条，正式记忆 325 → 324，保留 325 条来源贡献；累计 87 次实际请求（修复前 3 次、修复后 84 次），一次 `provider_response_incomplete` 后重试成功，86 份判断缓存均通过结构校验，3 次复用缓存。条目结果为 239 条无候选、21 条包含、63 条相关或不同、1 条不确定、1 条合并。Admin 实际页面确认总览 324、待处理 0、记忆向量覆盖 324/324，以及上述按需诊断分类。

SQLite 完整性检查通过、无外键违例；原始 `data` 仍为 schema 11。没有提交、推送或部署。候选门槛漏召回与实际模型的一次疑似误合并已形成失败样例，语义质量未验收；不能把本计划完成表述成已解决所有真实重复，或生产旧零合并根因已全部确认。

## 候选覆盖与判断质量边界

实际模型对 7 条英文控制样例完成 6 次有效判断，产生 2 次等价合并、保留包含与矛盾对，最终 5 条正式记忆对应 7 条来源贡献。另一个中英文控制集为 6 条，实际完成 1 次判断、1 次合并；其中 KV Cache 等价译文的实际余弦为 0.746789，被既定 0.75 门槛挡在模型之前。这不是模型拒绝合并。

随后用仓库标注语料的 59 条不同原文生成实际 `embedding-3` 向量，检查 60 个方向性关系（正反方向不视作独立样本）。20 个等价方向均超过 0.75，最低 0.753816；30 个不同方向也全部超过 0.75。原始 325 条记忆的向量门槛从 0.75 降到 0.70，会把通过的无向对从 31 对扩大到 91 对、覆盖条目从 54 条扩大到 122 条。这些有限样本不支持把余弦当等价判定，也不足以证明一个新的通用门槛，因此本轮保留既定阈值并记录已知漏召回。

真实全量测试出现一对模型判为等价的程序操作说明，但其中一侧额外包含验证步骤。按完整等价标准仍需质疑该判断，不能因为 JSON 和候选编号校验通过就记为语义质量验收通过。保留双方来源贡献及本地审查材料；生产旧 87 次调用仍缺少原始校验／关系证据，不能回溯断言其原因。


## 实测发现：可选维度被误当成必填项

用户配置了智谱 `embedding-3` 并完成 325/325 条记忆向量，数据库实际存有 2048 维数据；模型 capability 中 `dimension=null`，与 UI“预期输出维度（校验用，可选）”一致。旧 `organization_vector_candidates` 却在该字段为空时立即返回空列表，向量覆盖完整也不会参加整理。这是本地真实配置复现出的代码缺陷，之前所有替身均填写 `Some(64)`，因此未覆盖。

新增未填维度的回归先失败（保留 2 条），修复后通过（等价内容合为 1 条）。修复从当前种子记忆、当前模型 profile 和精确输入哈希对应的有效向量取得实际维度，仅比较相同实际维度的分区；显式维度继续作为校验约束，不借用其他对象或旧 profile 的维度。

迁移 0026 按实际记忆向量与有效角色绑定，仅将受影响的已完成独立贡献重新排队。Vault 专属绑定优先于全局绑定；已归组、没有向量、使用显式维度或被其他绑定覆盖的工作不重排。保留缓存、来源和规范文件，不重新提取。

本地 schema-25 副本升级实测：暂停值始终为 1，向量记录始终 617，正式记忆始终 325，判断缓存始终 3；24 条原已完成工作重新排队，待处理从 301 恢复为 325。现已恢复该实例进行真正包含向量候选的全链路测试。原只有词法的一轮已完成：65 次有效请求、0 次无效输出、0 次合并；260 条无候选、17 条包含、48 条相关或不同。
