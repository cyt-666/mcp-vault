# ExecPlan：增量记忆归并与旧算法自动退出

## 状态与目标

- 创建及更新日期：2026-09-07。
- 执行者：Codex。
- 状态：实现及本地工程验收完成。
- 用户授权：完整实现按新增／变更贡献归并、历史一次性整理、手动执行／暂停／继续；新版本启动时删除旧自动合并任务和记录，从当前来源贡献重新开始。

## 用户可见结果

新事实在来源集合发布后进入有界归并任务；系统保留完整来源贡献，查找少量可信候选，一次结构化请求判断新事实与候选的完整等价关系。没有候选、相关、包含或不确定时保留独立记忆。系统按条目报告进度，不创建全库两两组合队列。管理页面提供立即整理、暂停、继续及明确的重新检查操作。

升级无需访问管理页、重新提取原笔记或重新绑定模型。旧任务、候选、决策、正文改写缓存和旧进度自动退出。旧正式分组通过 Vault Core 从当前来源贡献恢复成独立正式记忆，再运行新方案。原笔记、显式记忆、来源暂停状态及审计／修订恢复记录保持有效；不从历史猜测恢复旧算法已经移除的来源条目。

## 设计与风险

1. 新任务使用 `memory.organize`，旧任务不再注册；迁移删除旧算法任务及派生记录，保留未完成正式文件操作，先恢复后切换。
2. 每个 Vault 保存一次切换状态、暂停状态和来源脏记录；每条贡献保存当前语义／来源输入标识、待处理状态和结果。来源发布事务同时标记该来源；变更只维护其受影响正式支持。无变化的启动只检查元数据。
3. 候选来自当前正式记忆的词法和有效向量，统一过滤、排序并限量。拒绝显式记忆、自身、同组、明显不兼容和低相关候选。模型使用请求内编号，结果必须完整、无重复且引用有效。
4. 归并只增加经验证的来源支持，不拼接正文，不依赖传递相似性。并发变化在正式发布时重新校验。候选结果缓存绑定确切输入和模型／规则；已完成贡献不因仅模型切换再次排队。
5. 升级重建逐个正式对象保存文件操作，不清空尚未恢复的操作日志。切换可中断重试，首次完成后不再执行。已被旧算法压缩的来源集合以当前规范文件为准；不重放旧审计或历史生成结果。
6. 手动重新检查只使归并工作重新待处理，保留来源和正式正文；暂停不破坏本地来源失效与恢复。请求和状态均 Vault 绑定、认证和 CSRF 保护。

## 决策与发现

- 旧模型判断缓存不能作为新处理完成依据。
- 旧正式记忆文件必须通过受控发布更新，不能仅删除 SQLite 分组投影，否则 Markdown 重建会恢复旧结果。
- 复用正式记忆／来源支持与发布恢复，替换调度内核；正常流程移除包含删除和句子改写。
- 新算法允许漏合并，不以消除所有相似文本作为完成条件。

- 正式发布同时提交新条目的完成标记和成功合并计数，避免崩溃后漏记或重复判断。
- 新增来源仍需遵守模型退避；手动立即执行可显式唤醒等待任务。
- 已有组的向量最后到达时，有界补查最多 8 个独立邻居，不重新判断组内成员。

## 回滚与恢复

旧队列及缓存删除不可逆，也不应重新导入。需要完整回滚旧版本时同时还原升级前数据库与 Vault 备份；不能仅回滚二进制。新任务的待处理条目与正式操作日志支持重启继续；来源正文和显式记忆不依赖旧缓存。
