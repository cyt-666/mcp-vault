# 无损记忆整合真实验证

日期：2026-09-08，更新：2026-09-09。状态：真实服务质量验收不通过，错误组已恢复，整理保持暂停。关联 [ADR-0032](../../adr/0032-lossless-memory-consolidation.md)与[执行计划](../active/organization-quality-improvement.md)。

## 当前审查结论

当前实现不能按“自动无损整合”验收。全量续跑实际发布了两处语义丢失：TUI 默认行为被条件化，以及 GPU 的先后步骤被拆为无序事实。两次都通过了模型的完整覆盖检查；第二次发生在加强方向约束并通过 10 项真实控制检查之后。逐项来源检查有作用，但同一模型的支持／覆盖判定仍可能漏掉命题关系，不能作为无损的充分证明。

两个错误组都已按当前原始贡献安全恢复。最终保留 320 条正式记忆，包含 5 个逐项审阅的两成员组；325 条原始贡献、27 篇来源笔记不变，320/320 当前向量完整，规范文件与投影一致。整理暂停，队列为已处理 207/325、待处理 118。全量没有跑完，不能报告全量准确率、全量候选覆盖或完成后的零重复调用验收。

继续付费回放不能推翻已经出现的反例。本轮审查保留为质量阻断，不把提示词局部改进当作已解决。下一轮需要先确定正式召回的可靠性边界：保守保留原文并对可确定的重复做消除，或将生成的整合文本作为需要复核的建议。两者都改变当前自动发布语义，应先修订 ADR 和验收要求。这里只提出待决方向，没有擅自变更为需要人工逐条操作的产品流程。

## 验收口径

用户允许整合相容的重叠内容，同时完整保留参与贡献的细节及逐项来源。语义质量只根据真实 MiMo 返回、实际发布正文与原始贡献的逐项对照评价。工程替身用于验证调度、暂停、来源失效及恢复，不能证明自然语言判断准确。

当前基线是[前轮全量实测](organization-real-model-validation-20260908.md)中的 325 → 324；其中唯一合并有遗漏 GPU 验证步骤的疑点，因此不能把它记为正确合并。新规则必须保留检查实际设备的步骤，也必须保留另一侧明确提及的可用性检查 API。

原始贡献与规范文件保存在隔离本地数据目录。实际模型是用户已授权的 `mimo-v2.5` 与 `embedding-3`。原始私有正文、模型返回和只读检查材料保存在 Git 忽略目录，不写入本报告。未修改生产数据。

## 提案实验

六组未发布提案包含四组相容重叠及两组不宜合并的范围／冲突对。首轮高层合并选择符合预期，但某些额外职责被错误归属到只提供简短描述的来源；同模型的整体复核也放过了这些错误。

### 正文长度与可读性

无损和来源精确不等于每组正文一定更短。第四轮模块组原始两段共 286 个字符，正式正文 317 个字符，包含事实编号与换行，且“执行引擎”存在局部重复；GPU 组为 392 → 331 个字符。这里统计 Unicode 字符，不是 Token，也没有把来源元数据计算进去。该可读性限制需要保留，不能只用对象数量下降证明压缩收益。
