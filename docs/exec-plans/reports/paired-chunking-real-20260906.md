# 真实模型分块对照：2026-09-06

结论：**本组样本未显示检索更准确；正确笔记排名持平，首选分块的答案覆盖下降。**
用户绑定分块模型后明确要求真实测试；只读使用隔离本地配置，没有写入真实笔记、修改绑定或部署。

## 固定条件与方法

- LLM：用户绑定的 `mimo-v2.5`；embedding：`embedding-3`，实际输出 2048 维，两组完全相同。
- 8 篇合成笔记，每篇约 2.6 KiB，含相似主题、教程、实际条件、否定和下一阶段。
  16 个有答案问题（含中英文提问），4 个无答案问题。原文和标签在调用模型前固定。
- 规则组与模型组经过实际 IndexService 分块准备流程；模型组保留生产默认大小/时间限制及规则回退。
  不通过重建已有用户向量触发，全部写入临时 Vault Core。
- 文本相同的输入只生成一次真实向量，供两组共用。共 47 个唯一输入；完整向量已保存，可零调用重算。
- 使用生产 `exact_cosine_similarity`，按每篇笔记最佳分块聚合并排序。
  这是**纯语义对照**，没有调用完整公开混合 recall，也没有把关键词结果混入向量效果。
- 除笔记排名，还检查最高分块是否包含事先标注的完整答案片段。两个失败项另经原文/命中内容核对。

## 实测结果

| 指标 | 规则分块 | 启用 LLM 分块的实际流程 |
|---|---:|---:|
| 分块总数 | 16 | 23 |
| 真正采用模型分组的笔记 | 0 | 2/8 |
| 回退到规则的笔记 | 不适用 | 6/8 |
| 正确笔记排名第一 | 16/16 | 16/16 |
| Recall@5 / MRR@5 | 1.0 / 1.0 | 1.0 / 1.0 |
| 首选分块含完整答案 | 16/16（100%） | 14/16（87.5%） |
| 无答案题仍有非负相似度候选 | 4/4 | 4/4 |

真正采用 LLM 的两篇是 `cedar-cache` 和 `birch-backup`，分别拆成 6 块、5 块。
这两篇对应的四题中，首选分块答案覆盖从 4/4 降到 2/4；其余六篇实际回退，因此不能把它们的持平
当作模型分组有效的证据。无答案题的指标只表示存在相似候选，不是模型已经给出了错误答案。

## 两处退步的证据

1. 问“在什么情况下允许复用雪松的回答缓存？”：规则组最高分块含租户身份、权限版本、文档修订号
   必须同时一致的完整条件（cosine 0.5289606）。模型分组后最高分块变成“撤销成员权限后清除缓存”
   （0.4779235），确属同一笔记，却没有回答复用条件。
2. 问“Can a Birch backup operator restore data without approval?”：规则组最高分块含“恢复操作另需
   管理员批准”（0.4630927）。模型分组后命中“恢复失败保留归档和日志，再验证密钥”
   （0.4598999），缺少审批限制。

不是答案从原文中丢失：两个正确答案都完整保存在其他模型分块里。模型把相关条件拆开后，当前
“每篇取最高分块”的向量检索选择了主题相近、但未包含所问事实的分块。更多、更细的分块不自动
带来更好的答案段落定位。

## 成本、限制与未确定项

实际 **11 次调用**：8 次 LLM，3 批 embedding；无重试，未使用满 24 次上限，未为追求好结果重跑。
没有修改维度、放宽大小限制、调整门槛、改标签或针对结果调提示词。

6 篇规则回退是确定观察。当前保存的回退记录没有分开记录 Provider 失败、超时和分组校验失败，
本轮不能精确归因，不能仅凭耗时就断言都是超时。这也暴露出回退诊断信息不足。

样本只有 8 篇且内容模板相近，笔记排名已到上限；成功模型分组仅 2 篇。结果不足以推断所有模型、
真实私人笔记或其他分块策略的优劣，也不能证明更换向量维度会改善结果。当前证据支持保留规则
分块作为可靠基线；模型分组仍是可选实验，不能作为默认效果提升承诺。
