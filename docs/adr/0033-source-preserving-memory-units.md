# ADR-0033：完整原文记忆单元与任务召回

- 状态：已接受，实施中。
- 日期：2026-09-09。
- 授权：用户批准新记忆重构计划，允许生产切换时全部抛弃旧记忆数据，不转换旧记录。
- 替代：ADR-0031／0032 的正式正文合并；ADR-0026 中模型重写自动正文及旧契约兼容相关决定。Vault 隔离、来源当前资格、明确所有权及模型不可读历史等原则继续成立。
- 执行计划：[新记忆系统](../exec-plans/active/memory-system-v3.md)。

## 问题

真实服务逐项支持／覆盖检查仍放行了默认行为条件化和有序步骤丢失。生成摘要不可作为唯一正式表达，模型自评不构成语义无损证明。用户目标是可靠地接续工作、利用约定和经验，而不是持续减少存储对象数量。

## 决定

明确记忆直接保存授权正文。自动记忆聚焦约定、决策、状态及实践经验，模型从服务编号的完整原文单元中选择，服务提取正文并绑定当前来源。普通教程和通识资料保持知识检索用途。一次性 PPT／演讲／报告的排版、逐页文案、素材、命名和纯呈现步骤即使真实发生或写成“已决定”，仍留在原笔记按需检索；一次任务的重要安全前提、阻塞和已承诺下一步仍可选择，即使只执行一次。混合来源逐单元判断，不能按文件类型整体拒绝。参考架构事实没有当前项目明确采纳关系时不自动变成项目约定；保留原文实际给出的时间、版本和范围，未注明日期时不猜当前有效性，旧文档中的作者亲历经验仍按原有范围判断。选择的最小完整单元必须保留前提、适用范围、顺序、例外和验证步骤。原文摘录仍需完整上下文与质量验收，不宣称能够自动穷尽笔记知识。

完整单元保留标题、范围、前提、顺序、例外及验证步骤；模型分类、检索说明和主题概览为派生数据，不能替代正文或递归成为证据。单元来源哈希与修订控制发布及当前读取。明确记忆独立维护；自动项删除原子暂停来源，明确恢复后再生成。

自动提取先选择最小源单元，再对有父子或兄弟关系的结果执行有界完整性审查。审查输入只包含实际展示的源正文，严格限制为 32 个单元和 60 KiB 序列化 JSON；每个首轮 ID 只能归入一次审查、确定性省略或无关系直通。父替代必须由同一 scope 中实际可见的完整父正文和显式 replace_parent 动作授权，不能由字节包含关系推导。首轮和审查阶段使用不同的缓存阶段、schema、profile 与输入哈希，全部审查完成后才允许原子发布。

召回根据任务选择完整单元，去重只作用于明确相同正文／范围的展示，不能据相似性删改来源。模型概览单独标识、引用具体单元，失效时返回确定性导航。普通召回不调用生成模型，外部能力不可用时保留关键词路径。

自动单元直接返回原始笔记内容，因此需要 memory:read 和 vault:read；明确记忆继续按自身权限访问。生成内容和笔记都作为资料，不是更高优先级指令。

新 schema 和规范格式独立；不读取、转换或接管旧记忆。生产一次性离线初始化清除旧记忆业务数据及受管文件，保留普通 Vault 和服务操作配置，具备阶段恢复与完成幂等。普通启动不得反复清零。

### 在线受控初始化入口（2026-09-11 修订）

离线 CLI 继续保留为运维入口，但不再是唯一入口。Admin 可以在已认证、通过 Origin/CSRF 校验并绑定当前 Vault 的页面中查看只读预览，只有明确确认“清理旧 memory、保留普通 Vault 内容”后，才能创建后台初始化任务。确认接口立即返回 `202 Accepted`；初始化不在普通请求或普通 job handler 的 operation guard 中等待自身维护排空。

初始化、Backup、Restore 和维护恢复共享同一个进程级独占维护 lease。lease 先阻止新的 data-plane/Admin 普通写操作，再有限时等待已受理 operation/write admission 排空；超时恢复原维护模式并保持数据不变。Offline 期间仍允许 Admin 登录、身份会话、必要 Vault 列表、初始化预览/状态/确认/续跑和维护恢复路径，不能借此开放全部 Admin 写入。

初始化任务状态、阶段、manifest checkpoint、进度和安全错误码持久化在 Vault 作用域内。进程重启只展示 `required`、`clearing` 或失败状态，不自动清理；管理员必须显式续跑。显式确认并持久化 manifest 后，初始化不重放受管旧 memory namespace 的 Core intent，而是先证明 journal 的完整操作路径都在 `_mcp-vault/memory/` 内，再将其终结为 `discarded`；随后仍由 Vault Core 按 manifest hash 删除文件。普通 Vault/V3 路径或范围无法证明的 journal 保持原样并阻止初始化；普通 Vault 路径的 journal 留给常规 Core recovery，不被本次 memory 清理改动。ready 分支保持幂等并且不触碰新 v3 memory。CLI 的 offline-exclusive 检查继续有效，受控在线任务只能通过明确的维护 permit 访问 Core 和 State 初始化操作。

## 后果与验收

允许存储存在重复、自动记忆更少及个别完整单元更长，通过任务选择和导航控制上下文成本。无需日常项目配置或人工候选审核；不建立永久合并事实图。

验收依据是完整原文／当前来源约束、真实任务下的相关性和工作结果、删除与重启行为、预算与成本，而不是模型合并比例。工程、真实模型与生产验收分别完成，具体用例和切换顺序见执行计划。
